What this measures

Each surface holds 25 positives, 15 negatives and 10 near-misses. A positive fact is true only when its quote is in the cited file. A negative case must produce no mapped finding. A near-miss names the lookalike that must not be emitted: Minecraft Bedrock is not AWS Bedrock, a CSS cursor is not the Cursor IDE, Claude Bernard is not Claude.

These are not private tenant dumps. One documented format per surface. That is the sampling frame.

  • code. Minimal application tree (Python or Node, plus optional agent config).
  • identity. Okta GET /api/v1/apps JSON export, status ACTIVE.
  • gateway. LiteLLM-style JSONL spend log (one record).
  • lowcode. n8n workflow export JSON (id, name, nodes, connections).
  • saas. Slack admin approved-app record JSON, with workspace id.
  • cloud. JSONL record in the AWS inventory dump shape (agent or lambda).
  • endpoint. Linux home-directory fragment with vendor config paths.
  • network. JSONL DNS log row with src_ip, query and ts.
  • runtime. osquery processes JSON array (name, path, cmdline, pid).

How a point is scored

Fact-level precision, recall and F1 are primary. A positive case is detected if any planted fact comes back. Any mapped finding on a negative or near-miss is a false positive. Specificity, false-positive rate, balanced accuracy and Matthews correlation use that case table. Crashes and timeouts leave the denominator and are counted as errors. A 1,000-draw bootstrap over cases gives a 95% interval on fact F1.

Estate recall is the harsher number: positives on surfaces the tool cannot read count as misses. Unscanned negatives are not called true negatives. The lexicon reference applies the published alias list to the artifact text, including paths.

Tools that need a vendor token or a live Kubernetes cluster were probed and then marked not run. Their F1 is left blank on purpose. Labels were not edited to delete a miss after the tools ran.
